# إدارة مخزن الدولية — نظام إدارة مخزون إكسسوارات مصنع الملابس

تطبيق ويب عربي متكامل (**RTL**) لإدارة مخازن إكسسوارات مصانع الملابس (أزرار، سوست، خيوط، أستك، تيكت، كباسين، دانتيل، فازلين) مع حساب تلقائي للأرصدة، تتبع أرصدة كل عميل بالمخزن، سجل حركات بالوقت والتاريخ واسم القائم بالعملية، نظام تنبيهات بالحد الأدنى، وتصدير التقارير إلى Excel و Word وواتساب.

## المزايا الرئيسية
- **لوحة تحكم شاملة**: مؤشرات الرصيد الفعلي، المخصص للعملاء، الرصيد الحر، التنبيهات الحرجة، ورسم بياني أسبوعي للوارد والمنصرف.
- **إدارة الأصناف**: إضافة وتعديل وحذف الأصناف، تعديل الرصيد مباشرة، وإظهار الأصناف ذات الرصيد الصفري دائماً بدون إخفاء.
- **حساب أرصدة العملاء**: متابعة كميات كل عميل أو خط إنتاج داخل المخزن، مع إمكانية التخصيص أو الصرف المباشر من رصيد العميل.
- **إضافة وصرف المخزون مع الحساب التلقائي**: خصم وإضافة تلقائية مع منع الصرف بالسالب أو تجاوز رصيد العميل/الرصيد الحر.
- **سجل الحركات الزمني**: توثيق التاريخ والوقت، نوع الحركة، الرصيد قبل وبعد، واسم الشخص الذي قام بالإضافة أو الصرف.
- **صور الأصناف والحركات**: حفظ صورة ثابتة للصنف من نافذة تعديله، إلى جانب الصور الاختيارية لكل حركة إضافة أو صرف، في مخزن خاص.
- **تنبيهات انخفاض الرصيد**: تحديد حد التنبيه (`minThreshold`) لكل صنف على حدة من لوحة المدير.
- **التقارير والتصدير والواتساب**: فلاتر (يومي / أسبوعي / شهري / الكل / فترة مخصصة)، طباعة، تصدير **Excel (.xlsx)** و **Word (.doc)**، وإرسال ملخص التقرير مباشرة عبر واتساب إلى `+20 11 04155183` (قابل للتعديل من الإعدادات).
- **حسابات ومزامنة آمنة عبر Supabase**: تسجيل الدخول من Supabase Auth، وقراءة البيانات للمستخدم النشط، وتعديلها لمدير النظام فقط. لا تُخزّن كلمات المرور في كود الواجهة.
- **تحديث واجهة المشرفة تلقائياً**: تُحدّث بيانات المخزون وسجل الحركات من Supabase كل 15 ثانية أثناء بقاء صفحة المشرفة مفتوحة.
- **محادثة خاصة لحظية**: محادثة محفوظة بين حساب المدير «محمد رضا» وحساب المشرفة «داليا محمد»، مع مؤشر القراءة والإشعارات عبر Supabase Realtime.
- **دخول سريع على الجهاز نفسه**: بعد تسجيل الدخول يظهر الحساب في قائمة الدخول السريع؛ الاختيار يملأ البريد الإلكتروني فقط، ولا تُحفظ كلمة المرور محلياً.

## التشغيل محلياً (Development)

```bash
npm install --legacy-peer-deps
npm run dev
```

## إعداد Supabase والحسابات

1. أنشئ مشروعاً جديداً على [Supabase](https://supabase.com).
2. افتح **SQL Editor** ونفّذ محتوى الملف `supabase_schema.sql`. يفعّل هذا سياسات تمنع الوصول المجهول وتسمح للمستخدم النشط بالقراءة ولمدير النظام بالكتابة. يتضمن الملف أيضاً bucket خاصاً لصور الأصناف والحركات (JPG / PNG / WebP حتى 8 ميجابايت)، مع القراءة للمستخدم النشط والرفع والتحديث للمدير فقط.
3. من **Authentication → Users** أنشئ حساباً لكل مستخدم، وعطّل التسجيل العام حتى لا ينشئ الغرباء حسابات.
4. أضف ملف صلاحية لكل حساب من SQL Editor، مع استبدال البريد ومعرّف المستخدم (UUID) الظاهر بجانب الحساب في Supabase:

```sql
insert into public.user_profiles (id, name, email, role)
select id, 'محمد رضا', email, 'admin'
from auth.users
where email = 'admin@example.com';

insert into public.user_profiles (id, name, email, role)
select id, 'داليا محمد', email, 'manager'
from auth.users
where email = 'dalia@example.com';
```

استخدم `admin` لمدير النظام و`manager` للمشرفة ذات صلاحية العرض فقط. يربط المخطط المحادثة بمعرّف UUID للحساب النشط الوحيد لكل دور، ولا يعتمد على الاسم لاختيار الحساب. إذا وُجد أكثر من حساب نشط لدور واحد فلن يسجله المخطط للمحادثة، منعاً لربط حساب خاطئ.

للتحقق من الحسابين اللذين رُبطا فعلياً بعد تشغيل المخطط:

```sql
select cp.participant_key, cp.user_id, p.name, p.role, p.active
from public.chat_participants cp
join public.user_profiles p on p.id = cp.user_id
order by cp.participant_key;
```

5. انسخ `.env.example` إلى `.env` وأضف بيانات المشروع. استخدم **Publishable key** فقط؛ لا تضع `service_role` في تطبيق المتصفح:

```env
VITE_SUPABASE_URL="https://YOUR_PROJECT.supabase.co"
VITE_SUPABASE_PUBLISHABLE_KEY="YOUR_SUPABASE_PUBLISHABLE_KEY"
```

## البناء والنشر

```bash
npm run build
```

يمكن نشر مجلد `dist/` الناتج على **GitHub Pages** أو **Vercel** أو **Netlify**. أضف متغيري `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` إلى إعدادات البناء في منصة الاستضافة.

على GitHub، أضف المتغيرين من **Settings → Secrets and variables → Actions → Variables**، ثم اختر **Settings → Pages → Build and deployment → GitHub Actions**. سير العمل في `.github/workflows/deploy.yml` يبني الموقع وينشره تلقائياً مع كل تحديث لفرع `main`.

> ملف `supabase_schema.sql` يقيّد الكتابة بمدير النظام، لكن تغييرات المستخدمين وأدوارهم تتم يدوياً في Supabase. لا ترفع أي ملف `.env` إلى GitHub.

> **للمشاريع التي أُعدّت مسبقاً:** نفّذ النسخة المحدّثة من `supabase_schema.sql` مرة واحدة من SQL Editor لإضافة المحادثة الخاصة وسياساتها، ومسارات صور الأصناف والحركات وإنشاء bucket وسياساته. العملية لا تحذف بياناتك الحالية أو سجل الرسائل.
